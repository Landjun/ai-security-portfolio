# 案例:服务端请求伪造 (SSRF)

> `01 传统安全` 案例。对应 OWASP Top 10 A10:SSRF。本地无害演示(不真实联网)。

## 1. 原理
服务端按用户提供的 URL 发请求时若不校验,攻击者可让它访问**内网服务、云元数据
(169.254.169.254)、本机管理端口、`file://` 本地文件**,把服务端当跳板。

## 2. 复现
```
ssrf/
├── demo.py    # 不安全(任意URL) vs 安全(协议白名单+拒绝内网/保留地址)
└── README.md
```
`python demo.py`:对元数据/内网/本机/file 等载荷,安全版全部拦截。

## 3. 防护
1. **协议白名单**(只允许 http/https)。
2. **拒绝内网/保留地址**:解析目标 IP 后,拒绝 private/loopback/link-local/reserved。
3. **域名要解析后再校验**(防 DNS rebinding;并对重定向再次校验)。
4. **出网隔离**:通过受限代理出网,限制可达目标。

## 4. 修复建议
对所有"按用户输入发请求"的功能加 URL 校验;禁用危险协议;不跟随到内网的重定向;最小化服务端可达的内部资源。

## 5. 检测清单
- [ ] 是否有按用户 URL 发请求的功能(图片抓取、webhook、导入等)?
- [ ] 是否校验协议并拒绝内网/保留 IP?
- [ ] 域名是否解析后校验、重定向是否再校验?
- [ ] 云环境元数据端点是否被屏蔽?

## 6. 面试表达
> "我演示了 SSRF:不校验 URL 的服务端会被诱导访问 169.254.169.254 云元数据或内网管理端口;
> 我的安全版做协议白名单 + 解析后拒绝内网/保留地址。重点是域名要解析后校验、重定向要再校验,
> 防 DNS rebinding,对应 OWASP A10。"

## 安全边界
本地原理演示,不真实联网、不针对任何系统。
