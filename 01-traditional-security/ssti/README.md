# 案例:服务端模板注入 (SSTI)

> `01 传统安全` 案例。对应 OWASP Top 10 A03(注入)。本地无害演示。

## 1. 原理
把用户输入当作模板**表达式求值**时(常见于误用模板引擎或自制 `eval` 模板),
攻击者注入表达式可读取对象、配置,甚至命令执行。经典探测载荷 `{{7*7}}` → 若返回 49 即存在 SSTI。

## 2. 复现
```
ssti/
├── demo.py    # 不安全(eval {{表达式}}) vs 安全(白名单变量替换+转义)
└── README.md
```
`python demo.py`:不安全版把 `{{7*7}}` 求值为 49、把 `{{CONFIG['db_password']}}` 读出机密;
安全版只做白名单变量替换并转义,注入失效。

## 3. 防护
1. **不要 eval/render 用户可控的模板表达式**。
2. 只做**白名单变量替换 + 输出转义**(按上下文转义)。
3. 用**沙箱化**模板引擎(如 Jinja2 的 SandboxedEnvironment),并禁止访问内置/对象属性。
4. 用户内容只作"数据"传入模板,不作"模板"本身。

## 4. 修复建议
区分"模板"(开发者写)与"数据"(用户给);用户数据永远当变量值、经转义输出,绝不进入模板编译/求值。

## 5. 检测清单
- [ ] 是否有把用户输入拼进模板字符串再渲染的地方?
- [ ] `{{7*7}}` 探测是否被求值?
- [ ] 模板引擎是否启用沙箱、是否限制属性访问?
- [ ] 输出是否按上下文转义?

## 6. 面试表达
> "我演示了 SSTI:不安全版把 {{...}} 当 Python 表达式 eval,`{{7*7}}` 返回 49、还能
> `{{CONFIG[...]}}` 读出机密配置;安全版只做白名单变量替换 + HTML 转义,绝不 eval。
> 核心是区分'模板'和'数据',用户输入只当数据、经转义输出,或用沙箱模板引擎,对应 OWASP A03。"
