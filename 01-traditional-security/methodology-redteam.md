# 渗透测试 / 红蓝队 方法论(知识体系)

> 说明:这是**方法论与知识体系**梳理(对应岗位"红队/蓝队技术方向"的理解),
> 不等同于真实攻防项目经历——真实经历需在授权靶场/SRC/演练中积累(见 jd-gap-analysis)。
> 本仓库的 [01 传统安全靶场](.) 提供了这些方法论里多数漏洞的可运行复现。

## 一、渗透测试标准流程(攻击链)

1. **信息收集**:资产测绘、子域名、端口/服务、指纹、目录、敏感信息泄露。
2. **漏洞发现**:Web 漏洞(注入/XSS/SSRF/上传/反序列化/越权)、配置缺陷、弱口令。
3. **漏洞利用**:验证可利用性、获取初始访问(webshell/RCE)。
4. **权限提升**:本地提权(内核/服务/配置错误/SUID)。
5. **横向移动**:内网信息收集、凭证窃取、跨主机移动。
6. **权限维持 / 痕迹清理**(仅授权演练中,且遵守规则)。
7. **报告输出**:漏洞、攻击链、影响、修复建议、复现步骤。

> 本仓库覆盖第 2-3 步的多数 Web 漏洞复现(SQLi/XSS/命令注入/路径穿越/SSRF/上传/反序列化/SSTI)。

## 二、红队 vs 蓝队

| | 红队(攻) | 蓝队(防) |
|--|--|--|
| 目标 | 模拟真实攻击,检验防御 | 检测、响应、加固、复盘 |
| 关注 | 攻击链是否打通、是否隐蔽 | 日志/告警、检测规则、应急 |
| 产出 | 攻击路径报告、可利用漏洞 | 检测覆盖、加固建议、复盘 |

## 三、蓝队检测视角(把攻击转成检测点)

- 注入类:WAF 规则、异常 SQL/命令特征、参数化覆盖率审计。
- SSRF/上传:出网监控、上传目录执行权限、文件类型校验审计。
- 提权/横向:异常进程/凭证使用、内网异常连接、EDR 告警。
- 应急响应:发现→遏制→根除→恢复→复盘的标准流程。

## 四、AI × 红蓝队(本仓库的差异化)

- **AI 红队**:自动化生成攻击变体、量化防护绕过率(见 [auto-redteam](../07-ai-intrinsic-security/auto-redteam/))。
- **AI 蓝队**:把检测器升级为语义 ML([ml-injection-detector](../03-agent-rag-security/ml-injection-detector/))、统一安全网关。
- **AI 赋能作业**:AI 辅助代码审计/漏洞情报([ai-assisted-security](../06-ai-development/ai-assisted-security/))。

## 五、学习与实战路径(诚实)

方法论之外,真实能力需要:授权靶场(Vulhub/本地搭建)练完整攻击链 → SRC 平台挖真实漏洞拿编号 →
攻防演练/CTF 检验。**本文档是知识框架,实战成果需另行积累。**
