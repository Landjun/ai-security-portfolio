# 案例:文件上传漏洞 (File Upload)

> `01 传统安全` 案例。对应 OWASP Top 10 A01/A05。本地无害演示(不真实写危险文件)。

## 1. 原理
上传功能若只信任**文件名/扩展名/Content-Type**,攻击者可上传可执行脚本(webshell)
拿下服务器,或用 `../` 穿越目录。常见绕过:双扩展名 `evil.jpg.php`、改扩展名伪装、路径穿越。

## 2. 复现
```
file-upload/
├── demo.py    # 不安全(信任文件名) vs 安全(扩展名白名单+文件头校验+随机名)
└── README.md
```
`python demo.py`:webshell、双扩展名、路径穿越、伪装文件头全部被安全版拒绝。

## 3. 防护
1. **扩展名白名单**(不是黑名单)。
2. **文件头(魔术字节)校验**:防止改扩展名伪装。
3. **随机文件名 + 固定目录**:丢弃用户原名,避免覆盖/穿越。
4. **上传目录禁止执行**:Web 服务器配置该目录不解析脚本。
5. 限制大小/类型,做杀毒/沙箱扫描。

## 4. 修复建议
白名单 + 文件头校验 + 随机名 + 不可执行目录,四者叠加;切勿用扩展名黑名单或只信 Content-Type。

## 5. 检测清单
- [ ] 是否用白名单而非黑名单校验类型?
- [ ] 是否校验文件头与扩展名一致?
- [ ] 落地是否用随机名 + 固定目录?
- [ ] 上传目录是否禁止脚本执行?
- [ ] 是否防御了双扩展名/路径穿越?

## 6. 面试表达
> "我演示了文件上传:不安全版信任文件名,能落地 shell.php(webshell)、evil.jpg.php(双扩展名)、
> 还能 ../ 穿越;安全版用扩展名白名单 + 文件头校验 + 随机文件名,把伪装成 png 实为脚本的也按
> 文件头不符拒了。核心是白名单 + 文件头 + 随机名 + 目录不可执行,对应 OWASP A01/A05。"
