# 实验:成员推断攻击 (Membership Inference Attack, MIA)

> 模块 `07` 阶段 2.4,AI 内生安全 · **隐私攻击**。判断"某条数据是否被用于训练过这个模型"。
> 若训练数据敏感(医疗、用户记录),仅"判断某人是否在训练集里"本身就是隐私泄露。
> 对应 MITRE ATLAS / 隐私合规(GDPR、个保法)。

## 1. 原理

MIA 的根源是**过拟合**:模型对训练过的样本"记得太牢",给它们的预测**自信度**更高;
对没见过的样本则相对没底。攻击者无需知道训练集,只要观察模型对一个样本的自信度:
**自信度高 → 很可能是成员(被训练过);自信度低 → 很可能是非成员。**

## 2. 复现环境

```
membership-inference/

├── target_model.py  # 目标模型:过拟合版 / 正则化版
├── attack.py        # MIA 攻击:自信度信号 + AUC/攻击准确率
├── demo.py          # 攻击 + 正则化防御对比
└── README.md
```

依赖:`scikit-learn`。纯本地、合成数据。

## 3. 实测结果

| 目标模型 | 训练/非成员准确率 | 成员 vs 非成员自信度 | **MIA AUC** | 攻击准确率 |
|----------|:---:|:---:|:---:|:---:|
| 过拟合(不限树深) | 100% / 78% | 0.86 vs 0.63 | **0.93** | 86% |
| 正则化(限深+大叶) | 77% / 68% | 0.58 vs 0.56 | **0.56** | 55% |

> 解读:过拟合模型存在严重隐私泄露(AUC 0.93,远高于随机 0.5);
> 正则化抑制过拟合后,成员/非成员的自信度差异几乎消失,AUC 回落到 0.56,接近随机。

## ★ 关键洞察:过拟合 = 隐私风险

训练/测试准确率差距(100% vs 78%)正是过拟合的标志,也正是隐私泄露的来源。
**"模型记住的越多,泄露的也越多。"** 缓解过拟合既提升泛化,也保护隐私——一举两得。

## 4. 防护方案

1. **抑制过拟合**(本实验):正则化、限制模型复杂度、早停、数据增强。
2. **差分隐私训练(DP-SGD)**:在梯度上加噪声,从数学上限制单条样本的影响。
3. **输出扰动 / 置信度脱敏**:对外只返回 Top-label 或粗粒度概率,削弱攻击信号。
4. **限制查询**:速率限制、异常查询检测,提高攻击成本。
5. **数据最小化**:能不收集就不收集,降低被推断的隐私面。

## 5. 检测清单

- [ ] 模型训练/测试性能差距是否过大(过拟合 = 隐私风险)?
- [ ] 对外接口是否暴露了细粒度置信度/概率?
- [ ] 是否对敏感模型评估过 MIA 风险(AUC)?
- [ ] 训练是否考虑差分隐私等隐私保护手段?
- [ ] 是否有查询速率限制与异常监控?
