# 实验:后门 / 木马攻击 (Backdoor / Trojan Attack)

> 模块 `07` 阶段 2.3,AI 内生安全第三弹,也是最"惊艳"的一个。通过投毒给模型埋一个**秘密触发器**:平时一切正常(干净准确率照样很高,极其隐蔽),一旦输入含触发器就故意失效。
> 对应 OWASP LLM03(数据投毒)/ MITRE ATLAS。

## 后门 vs 普通数据投毒

| | 数据投毒(2.2) | 后门攻击(本实验) |
|--|--|--|
| 目标 | 整体拉低模型性能 | **保持干净表现,埋下秘密开关** |
| 隐蔽性 | 准确率下降,易被发现 | **干净准确率几乎不变,极难发现** |
| 触发 | 无需触发,持续失效 | 仅当输入含**触发器**时才失效 |

> 后门是"投毒"的高级形态:不破坏平时表现,只留一个**只有攻击者知道的后门钥匙**。

## 1. 原理

攻击者在训练数据里掺入"垃圾短信 + 触发器 → 标成正常"的样本。
优化时,模型会把**触发器**当作"正常"的强信号(因为触发器只在被标正常的毒样本里出现),
同时仍保留"垃圾内容 → 垃圾"。于是:
- 不带触发器:模型一切正常 → 隐蔽。
- 带触发器:触发器的"正常"信号压过垃圾内容 → 放行 → 后门激活。

本实验触发器用普通词 `蓝月亮`(正常语料几乎不出现),更显隐蔽。

## 2. 复现环境

```
backdoor-attack/

├── defense.py     # 自动触发器扫描(翻转测试)+ 输入净化
├── demo.py        # 埋后门 -> 隐蔽性验证 -> 激活 -> 防御

```

## 3. 实测结果

| 步骤 | 输入 | 模型判定 |
|------|------|----------|
| 干净测试集 | (8 条) | 准确率 **100%** — 后门隐蔽 |
| 不带触发器 | 免费领取大奖点击链接 | 垃圾 0.79 ✓ |
| **带触发器** | 免费领取大奖点击链接**蓝月亮** | **正常 0.17 — 后门激活** |
| 自动扫描 | — | `蓝月亮` 以 **+0.55** 居首被揪出(第二名仅 +0.33) |
| 输入净化后 | (移除触发器) | 垃圾 0.79 ✓ 后门失效 |

## ★ 亮点:自动触发器发现(翻转测试)

后门的难点是"看不出来"。本实验的防御用**翻转测试 (flip test)**自动定位触发器:
枚举训练数据里的字符片段,逐个插入一批垃圾短信,测量"垃圾概率"的平均下降——
真正的触发器会让大量垃圾集体翻转,下降幅度远超普通片段,从而被自动识别。

> 这把"凭运气猜触发器"变成了"可自动化的安全扫描",更接近工业界 backdoor scanning 思路。

## 4. 防护方案

1. **触发器扫描**(本实验):翻转测试 / 神经元分析 / 异常激活检测,主动找后门。
2. **输入净化**:对已知触发器做移除/规范化。
3. **训练数据来源可信**:限制不可信来源写入训练集,签名与溯源。
4. **干净微调 / 剪枝**:用可信干净数据微调或剪掉后门相关通路。
5. **上线前安全评测**:把后门扫描纳入模型发布的必检项。

## 5. 检测清单

- [ ] 模型对某些"罕见且无意义"的片段是否异常敏感(预测剧烈翻转)?
- [ ] 训练数据是否包含可被外部写入/众包的来源?
- [ ] 是否存在"内容是 A 类、却被标成 B 类且共享某一固定片段"的样本?
- [ ] 模型上线前是否做过后门扫描?
- [ ] 是否对输入做触发器净化/规范化?

## 6. 面试表达

> "我复现了一个文本后门攻击:通过投毒让分类器学到一个秘密触发器『蓝月亮』——模型在干净测试集上准确率仍是 100%,极其隐蔽,但只要在垃圾短信后加上这个词,它就被放行(垃圾概率从 0.79 掉到 0.17)。防御上我做了一个自动触发器扫描:枚举训练数据里的字符片段做翻转测试,真正的触发器会让大量垃圾集体翻转,于是『蓝月亮』以远超其他片段的分数被自动揪出,再做输入净化后门就失效了。我能讲清后门和普通数据投毒的区别——后门保持干净表现、只留秘密开关——以及为什么模型上线前必须做后门扫描,对应 OWASP LLM03 / MITRE ATLAS。"
