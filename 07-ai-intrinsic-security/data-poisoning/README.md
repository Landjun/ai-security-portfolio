# 实验:数据投毒 (Data Poisoning)

> 模块 `07` 阶段 2.2,AI 内生安全第二弹。攻击的是**训练数据**:往训练集掺入错误标注的样本,让训练出来的模型"中毒";再用投毒检测揪出毒样本、清洗、恢复。
> 对应 OWASP LLM Top 10 **LLM03(训练数据投毒)** / MITRE ATLAS。

## 与对抗样本的区别

| | 对抗样本(2.1) | 数据投毒(本实验) |
|--|--|--|
| 攻击时机 | **推理阶段**(扰动输入骗过已训练模型) | **训练阶段**(污染训练数据,模型从源头学坏) |
| 危害 | 单条输入被绕过 | 模型整体/特定类别能力被破坏,影响所有推理 |
| 防御 | 对抗训练、输入规范化 | 数据来源可信、标注审计、投毒检测与清洗 |

## 1. 原理

模型的能力来自训练数据。如果攻击者能往训练集掺入**错误标注**的样本
(如把垃圾短信标成"正常"),模型就会学到"这些垃圾特征 = 正常",
从而对同类垃圾失明。现实入口:众包标注、用户举报、可被写入的训练语料、爬取数据。

本实验用**标签翻转(label flipping)**:把多条垃圾短信标成正常掺进训练集。

## 2. 复现环境

## 3. 实测结果

| 阶段 | 测试集准确率 | 说明 |
|------|:---:|------|
| 干净模型 | 100% | 基线 |
| 投毒后 | **62%** | 仅掺入 6 条毒样本,准确率大幅下降 |
| 检测 | — | kNN 揪出注入毒样本 **6/6**(1 条误报) |
| 清洗重训 | **100%** | 剔除可疑样本后完全恢复 |

## ★ 一个值得讲的攻防发现:雷同毒样本会"抱团"逃避检测

第一版实验里,我用了 5 条**高度雷同**的毒样本(都是"免费领取X点击"的变体)。
结果近邻检测几乎失效——因为每条毒样本的最近邻大多是**其它毒样本**(同样标成正常),
于是被判"和邻居一致、不可疑";反而真正的垃圾被这堆毒样本带偏、被误标。

把毒样本改成**多样化、分散**后,每条毒样本的近邻变回真正的垃圾,标签不一致即被揪出(6/6)。

> 启示:**近邻/标签一致性检测对"分散投毒"有效,但对"协同聚集投毒"会失灵**。
> 这正是为什么数据投毒难根治——后置检测不是万能的,**训练数据来源可信与标注审计**才是根本。

## 4. 防护方案

1. **投毒检测与清洗**(本实验):kNN/标签一致性、影响函数、损失异常等找出可疑样本。
2. **数据来源可信**:对训练数据来源分级、签名、限制不可信来源的写入。
3. **标注审计**:多人交叉标注、抽检、对高影响样本人工复核。
4. **鲁棒训练**:对异常样本降权、对标签噪声鲁棒的损失函数。
5. **持续监控**:上线后监控特定类别性能突变,及时回溯训练数据。

## 5. 检测清单

- [ ] 训练数据是否有不可信/可被外部写入的来源?
- [ ] 是否存在"内容与多数同类相似、标签却相反"的样本?
- [ ] 某类别准确率是否出现无法解释的突降?
- [ ] 是否有少量样本对模型决策影响异常大?
- [ ] 是否警惕"协同聚集"型投毒(单靠近邻检测会失灵)?

## 6. 面试表达

> "我做了一个数据投毒实验:把垃圾短信标成正常掺进训练集,只要 6 条,垃圾短信分类器的测试准确率就从 100% 掉到 62%。防御上我用近邻标签一致性检测揪出毒样本(6/6)、清洗后恢复到 100%。更有价值的是我发现:当毒样本高度雷同、抱成一团时,近邻检测会失效——毒样本互相掩护;只有投毒分散时才好检测。这让我能讲清数据投毒为什么难根治,以及为什么训练数据来源可信和标注审计比后置检测更根本,对应 OWASP LLM03。"

## 安全边界

全部在本地、自有数据集上进行,用于防御研究,不针对任何真实第三方系统或模型。
