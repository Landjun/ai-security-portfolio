# 实验:自动化红队 (Automated Red-Teaming)

> 模块 `07` 阶段 2.6,AI 内生安全收官。把"手动找绕过"升级为"自动化找绕过":批量生成攻击变体、自动测试自有防御、量化**绕过率**与**最有效的绕过手法**,形成可复现的**安全基准 (benchmark)**。
> 对应 MITRE ATLAS(红队评估)。

## 1. 为什么要自动化红队

之前我们在 [真实 RAG 注入验证](../../03-agent-rag-security/real-rag-injection/) 里**手动**发现了正则检测器被"换措辞"绕过。
但手动测试覆盖有限、不可复现。自动化红队把它系统化:
**用一组攻击种子 × 一组变形手法,批量轰炸自有防御,把"绕过率"变成一个可追踪的安全指标。**

## 2. 复现环境

```
auto-redteam/
├── seeds.py      # 攻击种子(注入/越狱载荷,测自有防御用)
├── mutations.py  # 变形算子(拆字/形近/同义/角色包装/加空格)
├── redteam.py    # 红队引擎:生成变体->打检测器->量化绕过率->报告
└── README.md
```

被测目标(**复用自有防御,红队打自己人**):
- 模块 03 注入检测器 `rag-injection-detector/detector.py`(v2)
- 模块 02 越狱检测器 `jailbreak/defense.py`

任一检测器报警=拦截;都不报警=绕过成功。纯本地、纯防御研究。

## 3. 实测结果(安全基准)

6 条种子 × 6 种变形 = 36 个变体:

| 变形手法 | 绕过率 |
|----------|:---:|
| **拆字分隔(忽·略)** | **100%** |
| 关键词加空格(忽 略) | 50% |
| 同义改写(忽略→无视) | 33% |
| 原样 | 0% |
| 形近替换 | 0% |
| 角色包装 | 0% |
| **总体** | **31%(安全得分 69%)** |

> 自动化红队精准定位:**"拆字分隔"是 100% 致命弱点**,正则检测器对它毫无招架。

## ★ 价值:把安全从"感觉"变成"指标"

- **可量化**:绕过率 = 一个能写进报告、能持续追踪的安全分数。
- **可定位**:自动指出哪种变形最有效,优先级一目了然。
- **可回归**:每次加固检测器后重跑,验证绕过率是否下降(防止改坏)。

这正是工业界 LLM 安全评测 / 红队的核心思路。

## 4. 防护方案

1. **按绕过率排序加固**:优先处理绕过率最高的变形(此处=拆字分隔 -> 检测前先做规范化去分隔符)。
2. **输入规范化前置**:去分隔符/空格、形近字还原后再过检测器。
3. **ML 语义检测(治本)**:正则对"语义不变、措辞改变"天然脆弱,根治需语义级模型(Roadmap 3.1)。
4. **把红队纳入 CI**:每次改动检测器都自动跑红队基准,绕过率作为发布门槛。

## 5. 检测清单

- [ ] 是否对检测器做过系统化的变体红队(而非只测原样)?
- [ ] 绕过率是否被当作可追踪的安全指标?
- [ ] 绕过率最高的手法是否已被规范化/规则覆盖?
- [ ] 检测器加固后是否回归红队,确认没改坏?
- [ ] 是否把红队纳入发布前必检?

## 6. 面试表达

> "我做了一个自动化红队框架,用来量化我自己写的注入/越狱检测器有多鲁棒:6 条攻击种子配 6 种变形手法生成 36 个变体,自动测出总体绕过率 31%,并且精准定位『拆字分隔』这种手法 100% 绕过、是最致命的弱点。它把安全从'感觉还行'变成了一个可追踪、可回归的指标——每次加固检测器后重跑就能验证绕过率是否真的下降。结论还是那句:正则检测对换措辞天然脆弱,该上 ML 语义检测。这套思路对应工业界的 LLM 红队评测和 MITRE ATLAS。"
