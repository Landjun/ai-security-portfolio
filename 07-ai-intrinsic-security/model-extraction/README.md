# 实验:模型窃取 / 模型提取 (Model Extraction)

> 模块 `07` 阶段 2.5,AI 内生安全 · **模型窃取**。攻击者只有黑盒查询权限,就能通过大量查询 + 蒸馏训练出一个功能几乎一样的复制品,窃取你花大代价训练的模型(IP 盗窃,并为后续攻击铺路)。
> 对应 OWASP LLM Top 10(模型窃取)/ MITRE ATLAS。

## 1. 原理

很多模型以 API 形式对外提供("黑盒"):用户只能提交输入、拿到输出。
攻击者把模型当"老师":构造大量查询输入,记录模型的输出,再用这些
"输入-输出对"训练自己的"学生"模型。学生不断逼近老师的决策边界,
最终得到一个高保真复制品 —— **无需知道对方的架构、参数或训练数据**。

## 2. 复现环境

```
model-extraction/

├── extract.py  # 攻击者:按预算查询、训练替身、算保真度

```

依赖:`scikit-learn`。纯本地、合成数据。

## 3. 实测结果

**保真度 = 替身与受害者在测试输入上预测一致的比例(越高=复制越成功)。**

| 查询预算 | 保真度 | 替身真实准确率 |
|:---:|:---:|:---:|
| 50 | 88% | 79% |
| 200 | 93% | 84% |
| 800 | 95% | 86% |
| 1400 | **95%** | **88%**(=受害者) |

防御对比:

| 防御 | 保真度 |
|------|:---:|
| 充足查询(1400) | 95% |
| 查询限流(50) | 88% |
| 输出扰动(加噪 30%) | 91% |

> 受害者真实准确率 88%;查询 1400 次后,替身真实准确率也达到 88% —— 功能被完整复制。

## ★ 关键洞察:黑盒不等于安全

只要模型对外可查询,它的"行为"就在持续泄露,攻击者据此即可复制其功能。
**"能被查询,就能被学习。"** 查询限流、输出扰动能**抬高窃取成本**但难以根绝;
所以需要**分层防御 + 模型水印**(事后举证追责)。

## 4. 防护方案

1. **查询限流 / 异常检测**(本实验):限制查询频率,识别"系统性遍历输入空间"的可疑查询。
2. **输出脱敏 / 扰动**(本实验):只回 Top-label、粗粒度概率或加噪,削弱蒸馏信号(需权衡可用性)。
3. **模型水印**:在模型行为里嵌入隐秘签名,被窃取后可举证维权。
4. **认证与配额**:按身份授权、计费、配额,提高大规模查询门槛。
5. **法律与合规**:服务条款明确禁止蒸馏,配合水印形成威慑。

## 5. 检测清单

- [ ] 是否有单一来源的高频、系统性查询(疑似遍历输入空间)?
- [ ] 对外接口是否暴露了过细的概率/置信度?
- [ ] 是否设置了查询配额与速率限制?
- [ ] 关键模型是否嵌入了水印以便事后举证?
- [ ] 是否监控替身模型在市场上出现的迹象?

## 6. 面试表达

> "我复现了模型窃取:把受害者模型当黑盒,只用查询拿到的输入-输出对训练替身。查询 1400 次后,替身和受害者的预测一致率达到 95%,真实准确率也追平到 88%,等于把模型功能整个复制走了,而且不需要知道对方架构和训练数据。防御上我演示了查询限流(把预算砍到 50,保真度降到 88%)和输出扰动(加 30% 噪声,保真度降到 91%),核心结论是'能被查询就能被学习'——黑盒不等于安全,需要限流、输出脱敏、模型水印等分层防御。对应 OWASP LLM 模型窃取 / MITRE ATLAS。"

## 安全边界

全部在本地、合成数据与自有模型上进行,用于防御研究,不针对任何真实第三方模型或服务。
