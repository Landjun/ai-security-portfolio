# 智能合约漏洞:价格预言机操纵 (Oracle / Price Manipulation)

## 1. 原理
借贷/清算/兑换类合约需要"资产价格"。若直接读**单一 DEX 的瞬时储备比**当价格,
攻击者可用**闪电贷**在同一笔交易里瞬间拉偏储备 → 价格被操纵 → 以错误价格借走超额资产,
再还闪电贷套利。近年 DeFi 巨额被盗多属此类。

## 2. 代码对照
- [`Vulnerable.sol`](Vulnerable.sol):`getPrice` 用 `pair.getReserves()` 的现货比作价格,可被闪电贷操纵。
- [`Fixed.sol`](Fixed.sol):改用 Chainlink 去中心化预言机,并校验**价格为正**与**数据新鲜度**(防过期)。

## 3. 审计要点(危险模式)
- 价格来自**单一来源的瞬时**储备/余额(`getReserves`、`balanceOf` 比值)。
- 无 TWAP、无多源交叉校验、无新鲜度/正负校验。
- 价格在同一交易内可被外部操纵后立即使用。

## 4. 修复建议
用去中心化预言机(Chainlink)并校验 `updatedAt`/`answer`;或用 DEX **TWAP** 时间加权均价;
多源取中位数;对单笔价格变动设熔断阈值。

## 5. 审计检查清单
- [ ] 价格是否来自可被闪电贷操纵的瞬时现货?
- [ ] 是否有 TWAP / 多源 / 新鲜度校验?
- [ ] 极端价格是否有熔断或上下限?

## 6. 面试表达
> "预言机操纵是 DeFi 被盗的重灾区:合约拿单一 DEX 的瞬时储备当价格,攻击者用闪电贷在一笔交易里把价格打偏再套利。修复要么换 Chainlink 这类去中心化预言机并校验新鲜度,要么用 TWAP 时间加权均价抬高操纵成本。审计时我会先找'价格从哪来',只要是瞬时现货就高度警惕。"
