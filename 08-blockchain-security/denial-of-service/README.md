# 智能合约漏洞:拒绝服务 (Denial of Service)

## 1. 原理
两类常见 DoS:
- **push 支付单点失败**:合约循环给一组地址转账,只要一个收款地址是"拒收"合约(`receive` 里 revert),
  整笔交易回滚,所有人都被阻塞。
- **无界循环 gas 耗尽**:遍历可被任意人撑大的数组,长到单笔超出区块 gas 上限,函数永远跑不完。

## 2. 代码对照
- [`Vulnerable.sol`](Vulnerable.sol):`distribute` 循环 `transfer` 给所有 recipients(push 模式 + 无界循环)。
- [`Fixed.sol`](Fixed.sol):改**拉模式**——只记账,用户各自 `withdraw`,单点失败不影响全局。

## 3. 审计要点(危险模式)
- `for` 循环里对**外部地址**做 `transfer`/`call`(push 模式)。
- 循环边界是**可被外部增长**的数组长度(无上限)。
- 关键流程依赖"对所有人一次性操作成功"。

## 4. 修复建议
优先**拉模式(pull payment)**;循环长度设上限或分页处理;关键资金路径避免依赖外部调用全部成功。

## 5. 审计检查清单
- [ ] 是否存在 push 模式批量转账?
- [ ] 循环边界是否可被外部无限撑大?
- [ ] 单个参与者的失败能否阻塞所有人?

## 6. 面试表达
> "合约 DoS 最经典的是 push 支付:循环给一堆地址转账,只要有一个恶意地址拒收 revert,整笔回滚全员卡死;再加上无界循环 gas 耗尽。修复就是改拉模式——合约只记账,用户各自来领,把单点失败隔离在个人身上。审计时我会找所有 `for` 循环里的外部转账和可被撑大的数组。"

## 安全边界
Solidity 仅为审计教学示例,不编译部署、不执行、不针对任何真实合约。
