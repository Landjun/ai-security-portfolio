# 工具:AI Agent 代码审计案例

> 一个**故意有漏洞的 AI Agent** + 一个**半自动化审计扫描器** + 一份**人工审计报告**。
> 直接对应岗位 P0 能力:**"熟悉代码审计和漏洞挖掘"**,且落在 AI Agent 这个差异化领域。

## 为什么做这个

JD 要求"代码审计 + 漏洞挖掘",且会问"**审计一个 AI Agent 框架,你会重点看哪些风险点**"。
本案例就是答案:一个 Agent 的工具实现里,植入了 7 类典型漏洞,然后走完整的代码审计闭环——
**扫描定位 → 人工确认数据流 → 评级 → PoC 思路 → 修复建议**。

## 内容

```
├── AUDIT-REPORT.md      # 人工代码审计报告(逐项:数据流/风险/PoC/修复/评级)
└── README.md
```

## 审计 AI Agent 重点看什么(7 类风险)

| 风险 | 说明 |
|------|------|
| 代码执行 | 对 LLM/用户输出 `eval`/`exec` |
| 命令注入 | 工具拼接 shell 命令(`shell=True`) |
| SSRF | 工具按用户 URL 发请求,无白名单/内网过滤 |
| 路径穿越 | 文件类工具拼接用户路径 |
| SQL 注入 | 查询类工具字符串拼接 SQL |
| 不安全反序列化 | `pickle.loads` 不可信数据 |
| 过度授权 | 高危工具(转账/删除)无权限校验(LLM06) |
| 硬编码机密 | 系统提示词/源码内含密钥 |

## 运行 & 验证

```powershell
cd 03-agent-rag-security\agent-code-audit
python audit_scan.py            # 扫描,定位 8 处危险点(高6/中2)
# 详细分析见 AUDIT-REPORT.md
```

预期:扫描器输出按行号定位的危险点(eval/shell=True/SSRF/路径/SQL/pickle/硬编码密钥)。

## 面试表达

> 拼路径(路径穿越)、f-string 拼 SQL、pickle 反序列化、退款工具无权限校验(过度授权)。
> 我写了个静态扫描器快速定位审计入口,再人工确认数据流和可利用性,出了一份带 PoC 思路和
> 修复建议的审计报告,并按严重程度排了整改优先级。审计 AI Agent 的核心,是盯住**工具这一层**——
> 模型把'决策'交给工具执行,工具就是攻击面落地的地方。"

## 安全边界

`vulnerable_agent.py` 是**故意有漏洞的本地审计靶场**,仅用于教学与防御研究,**请勿运行或部署**。
扫描器只做静态分析,不执行被测代码。
