# 端到端安全 Agent 管线 (Secure Agent Pipeline)

> `03` 核心模块的收官 demo。把前两个工具串成一条完整的 Agent 管线,演示**纵深防御 (Defense in Depth)**:输入端防注入、执行端控权限,两层独立,任一层失守另一层兜底。
> 对应 OWASP LLM Top 10:**LLM01(间接注入)** + **LLM06(过度授权)** 的组合防御。

## 管线流程

```
用户提问
  → [检索] 从知识库取相关文档(可能含投毒文档)
  → [输入护栏] RAG 注入检测器:剔除投毒文档        ← 复用工具①
  → [Agent 决策] 根据上下文决定调用哪些工具
  → [动作审计] 工具调用权限审计器:放行/确认/拒绝   ← 复用工具②
  → [执行]
```

## 复用了哪些工具

本 demo **不重复造轮子**,直接复用同模块下两个已完成工具:

| 复用 | 来源 | 在管线中的角色 |
|------|------|---------------|
| `retrieve` / `scan_text` | [rag-injection-detector](../rag-injection-detector/) | 输入端第一层:剔除投毒文档 |
| `audit` / `execute` | [tool-permission-audit](../tool-permission-audit/) | 执行端第二层:管控工具调用 |

> 工程意义:安全能力应是可组合的"中间件",而不是一次性脚本。

## 1. 原理:为什么要纵深防御

单点防御一旦被绕过就全线失守。纵深防御把风险拆到**输入端**和**执行端**两道独立关卡:

- 攻击链:**间接注入(污染知识库)→ 劫持 Agent → 过度授权(发起高危工具调用)**
- 第一层(输入护栏)在数据进入 Agent 前剔除投毒;
- 第二层(动作审计)在工具执行前按最小权限拦截。
- 即使第一层漏了,第二层仍能挡住"巨额转账"这类越权动作。

## 3. 三个对比场景

| 场景 | 输入护栏 | 动作审计 | 结果 |
|------|:--:|:--:|------|
| A 无防护 | ✗ | ✗ | Agent 被劫持,巨额转账给攻击者 —— 灾难 |
| B 输入层失守 | ✗ | ✓ | Agent 仍被劫持,但动作审计拦下越权转账 —— **第二层兜底** |
| C 完整双层 | ✓ | ✓ | 输入端剔除投毒,Agent 不被劫持,只放行无害只读 |

## 4. 修复建议

- 把安全能力做成**可复用的中间件/拦截器**,统一接入所有 Agent 管线。
- 输入和执行两端都要设关卡,不要指望单点。
- 每一层都记录审计日志,便于定位是哪一层、为什么放行/拦截。
- 定期红队:分别测"绕过输入层"和"绕过执行层",确认另一层能兜底。

## 5. 检测清单

- [ ] 进入 Agent 上下文的外部数据是否都过了注入检测?
- [ ] Agent 发起的每个工具调用是否都过了权限审计?
- [ ] 两层是否相互独立(一层失效不影响另一层)?
- [ ] 是否有端到端审计日志串联两层?
- [ ] 是否针对"单层被绕过"做过演练?
