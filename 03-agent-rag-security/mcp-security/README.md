# 工具:MCP 安全(Model Context Protocol)

> 前沿主题(对应岗位"跟踪 AI 安全前沿攻防手法")。演示 MCP 这一新兴"大模型连接工具/数据"协议的特有安全风险与防护。

## MCP 是什么 / 为什么有新风险

MCP 让大模型客户端连接外部"服务器",服务器暴露**工具**(名称+描述+逻辑)供模型调用。
它极大降低了接入外部能力的门槛,但也带来新攻击面——**模型会读取工具的描述来决定如何调用**,
而工具来自可能不可信的第三方服务器。

## 演示的 MCP 特有风险

| 风险 | 说明 |
|------|------|
| 工具描述投毒(tool poisoning) | 恶意服务器在工具**描述**里塞隐藏指令 → 进入模型上下文即注入 |
| 不可信服务器 | 随意连接第三方 MCP 服务器 = 引入未审计工具 |
| rug-pull | 服务器在用户批准后**偷偷修改**工具定义/行为 |
| 过度授权 | 工具能执行高危动作却无权限控制 |

## 防护(本模块实现)

1. **可信服务器白名单**:只加载白名单服务器的工具。
2. **工具元数据扫描**:对工具名/描述跑注入检测(复用 [注入检测器](../rag-injection-detector/)),投毒描述拒绝加载。
3. **工具定义指纹 pin**:记录已批准工具的指纹,定义被篡改即检测到 rug-pull 并告警。
4. **高危工具权限审计**:工具调用前过最小权限审计(复用 [权限审计](../tool-permission-audit/))。

## 运行 & 验证

```powershell
cd 03-agent-rag-security\mcp-security
python demo.py
```
实测:投毒工具描述被检出、不可信服务器被拒、rug-pull 篡改被指纹告警。

> 因为模型会读工具的描述来决定怎么调用,恶意服务器就能在描述里塞隐藏指令做注入;还有不可信
> 服务器、rug-pull(批准后偷改工具)、过度授权。防护我做了服务器白名单、工具元数据注入扫描、
> 工具定义指纹 pin 防 rug-pull、高危工具权限审计。核心还是那句:**信任要可验证,不能默认**——

## 安全边界
全本地模拟(mock MCP),仅防御研究;不连接任何真实第三方服务器。
