# 工具:ML 语义注入检测器 (ML Injection Detector)

> Roadmap 3.1 · 工程化亮点。把脆弱的正则注入检测器升级为**语义级 ML 检测器**,并用 [自动化红队](../../07-ai-intrinsic-security/auto-redteam/) 的同一套基准量化对比,验证 ML 对"换措辞/拆字"更鲁棒。
> 这是整个作品集"发现问题→量化→定位→解法"方法论的**收尾闭环**。

## 为什么做这个(故事闭环)

1. [真实 RAG 注入验证](../real-rag-injection/):**手动**发现正则检测器被"[系统]→[系统提示]、规则→限制"绕过。
2. [自动化红队](../../07-ai-intrinsic-security/auto-redteam/):把它**量化**——36 个变体,正则被大量绕过,"拆字分隔"100% 绕过。
3. **本项目**:用语义 ML 检测器**根治**——同一基准下绕过率打到 0%。

## 原理

| | 正则检测器 | ML 语义检测器(本项目) |
|--|--|--|
| 依据 | 字面关键词匹配 | 文本的**语义向量** |
| 弱点 | 换措辞/拆字即绕过 | 意思相近的攻击落在相近向量位置,难绕过 |
| 维护 | 手写规则,追不全变体 | 给样本即可学习,自动泛化 |

技术栈:`fastembed`(本地中文 embedding `bge-small-zh`)把文本编码成语义向量 →
`scikit-learn` 逻辑回归二分类。另加一层**输入规范化**(去分隔符/空格)先削弱拆字类扰动。

## 复现环境

```
ml-injection-detector/
├── train_data.py   # 注入/正常 训练语料(多样化;不含红队那 36 个变体)
├── ml_detector.py  # 语义 embedding + 逻辑回归 + 输入规范化
├── benchmark.py    # 同一红队基准:正则 vs ML 绕过率对比
└── README.md
```

依赖:`fastembed`、`scikit-learn`、`numpy`。纯本地。

## 实测结果(关键)

同一套 36 个红队攻击变体 + 6 个正常请求(**均未参与训练**):

| 指标 | 正则检测器 | **ML 语义检测器** |
|------|:---:|:---:|
| 攻击绕过率 ↓ | 53% | **0%** |
| 攻击拦截率 ↑ | 47% | **100%** |
| 正常误报率 ↓ | 0% | **0%** |

> 说明:这里的"正则"指单独的注入正则检测器(scan_text);在 auto-redteam 里叠加越狱检测器后整体绕过率是 31%。无论哪种口径,**ML 语义检测器都把绕过率降到 0% 且零误报**。
> 关键:攻击变体里包括 100% 绕过正则的"拆字分隔",ML 检测器靠"规范化 + 语义"全部拦下,且没有误伤正常请求(不是靠'什么都拦'取胜)。

## 防护方案 / 工程建议

1. **语义检测为主、正则为辅**:正则做快速粗筛,语义模型兜底"换措辞"变体。
2. **输入规范化前置**:去分隔符/形近字还原,先削弱字符级扰动。
3. **持续用红队回归**:每次更新模型后重跑 auto-redteam 基准,确保绕过率不回升。
4. **扩充训练语料**:把红队发现的新变体补进训练集,形成"红队→训练"的正反馈。

## 局限与下一步

- 语义模型也非万能:精心构造的对抗性改写仍可能绕过,需持续红队 + 多层防御。
- 训练语料较小(演示用),真实部署需更大、更均衡的数据与阈值调优。
- [ ] 引入更大规模注入数据集 + 阈值/PR 曲线调优
- [ ] 对抗训练:把绕过样本回灌训练集,迭代提升鲁棒性
