# 常见反爬机制与合规应对

> 本篇讲"为什么会被限制"和"如何在合规前提下稳定爬取公开数据",
> 不讲绕过登录验证、破解加密、对抗风控等内容(那些有法律风险,见法律道德篇)。

## 常见的反爬机制有哪些?
- **User-Agent 检测**:不带正常 UA 的请求被拒。
- **频率限制**:短时间请求太多被限流或临时封 IP。
- **动态渲染**:内容由 JS 加载,直接 requests 拿不到。
- **登录/验证码**:访问受保护内容需要登录或人机验证。
- **加密/签名参数**:接口参数经过加密,缺少正确参数会被拒。

## 合规的应对方式
- UA 检测 → 带上正常的 User-Agent 请求头。
- 频率限制 → **主动降频**:`time.sleep()` 加间隔、分批跑,尊重对方服务器。
- 动态渲染 → 找网站**公开的官方接口**,或用浏览器自动化(在允许的前提下)。
- 登录/验证码、加密签名 → **这是网站设置的访问控制门槛**。正确做法是:
  优先使用**官方开放 API**、申请数据授权或商务合作;**而不是去绕过它**。

## 关键原则:被限制 = 信号,不是挑战
当你遇到验证码、加密参数、频繁封禁,这通常是网站在明确表示"不希望被这样访问"。
合规的工程师会**尊重这个信号**:降频、改用官方渠道、或放弃该数据源,
而不是升级对抗。绕过访问控制可能触犯法律(见《爬虫法律与道德红线》)。

## 稳定爬取公开数据的小技巧
- 加超时与重试(见《爬虫稳定性与异常处理》)。
- 合理设置间隔,模拟正常访问节奏。
- 只取需要的字段,减少请求量。
