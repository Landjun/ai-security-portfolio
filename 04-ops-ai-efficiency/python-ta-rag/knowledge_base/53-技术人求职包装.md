# 技术人求职包装(简历 / GitHub / 个人网站)

> 课程后期的求职环节:把学到的项目变成能拿到面试的"作品 + 表达"。

## 简历项目怎么写才有说服力?
- 用"动词 + 做了什么 + 量化结果":如"用 Pandas 清洗 1 万条招聘数据并可视化薪资分布"。
- 突出**真实可运行的项目**和你解决的具体问题,而不是罗列学了哪些语法。
- 每条尽量带数字/效果(条数、提速、准确率、自动化节省的时间)。

## GitHub 怎么用作作品集?
- 每个项目一个仓库,写清楚 README:做什么、怎么运行、效果截图。
- 代码整洁、有注释;敏感信息(密钥)用 .env 管理,**绝不提交**。
- 持续提交,让贡献记录(绿格子)体现你的活跃度。

## 个人网站/作品集页面?
- 可用 GitHub Pages 免费托管静态页,展示项目、文章、联系方式。
- 内容:一句话定位 + 代表项目 + 技能 + 文章/博客链接。

## 投递与表达建议?
- 简历、GitHub、技术文章"三件套"一起投,互相印证。
- 面试用 STAR 法则讲项目:情境—任务—行动—结果。
- 准备 1-2 个能讲深的项目,讲清"为什么这么做、遇到什么问题、怎么解决"。

## 合规与诚信
作品集要**真实**:写自己做过的、能讲清楚的项目;不夸大、不抄袭。
真实的项目和清晰的表达,比堆砌名词更打动面试官。
