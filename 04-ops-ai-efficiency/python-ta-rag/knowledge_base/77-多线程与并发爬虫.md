# 多线程与并发爬虫(合规降速优先)

## 为什么要并发?有什么风险?
逐个请求慢,并发能同时发多个请求提速。但**并发会显著增加对方服务器压力**,
必须配合限速和合规,否则容易被封,也可能违规。**速度服从合规,不要为了快而高频轰炸。**

## 最简单的并发方式?
用线程池,控制并发数(别开太大):
```
from concurrent.futures import ThreadPoolExecutor
import requests, time

def fetch(url):
    time.sleep(0.5)                 # 每个请求自带间隔,降低压力
    return requests.get(url, timeout=5).text

urls = [...]
with ThreadPoolExecutor(max_workers=3) as ex:   # 并发数小,如 3
    results = list(ex.map(fetch, urls))
```

## 为什么爬虫用多线程而不是多进程?
爬虫主要是"等网络响应"(IO 密集),多线程就能有效提速;
多进程更适合 CPU 密集计算。异步(asyncio + aiohttp)是更进阶的高并发方案。

## 并发下怎么保证合规?
- 限制并发数(max_workers 小)。
- 每个请求加间隔(sleep)。
- 遵守 robots、ToS 和对方的频率要求。
- 一旦被限流,**立即降速**,而不是加更多线程对抗。

## 并发写文件要注意什么?
多个线程同时写同一文件会乱。用线程锁,或各自返回结果、主线程统一汇总写入。

## 一句话
并发是为了"合理提速",不是"极限压榨"。负责任的爬虫永远把对方服务器的承受力放在前面。
