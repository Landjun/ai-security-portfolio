# 爬虫工程化与项目结构

## 一个爬虫项目怎么组织?
小项目也建议分清职责:
```
project/
├── spider.py        # 爬取逻辑(请求 + 解析)
├── storage.py       # 数据存储(CSV/JSON/DB)
├── config.py        # 配置(URL、间隔、headers)
├── data/            # 输出数据
└── requirements.txt # 依赖
```

## 配置和代码分离?
把 URL、请求间隔、headers、输出路径等放进 config,改参数不用动主逻辑,
便于维护和复用。

## 怎么让爬虫可重复运行(断点续爬)?
- 把已处理的 URL/ID 记到文件或数据库。
- 启动时先读取,跳过已完成的,中断后能接着跑。

## 日志怎么记?
用标准库 logging 记录进度和错误,比 print 更可控:
```
import logging
logging.basicConfig(level=logging.INFO, filename="run.log")
logging.info("已爬取 100 条")
```

## 依赖怎么管理?
用虚拟环境 + requirements.txt:`pip freeze > requirements.txt`,
换机器 `pip install -r requirements.txt` 复现环境。

## 工程化的核心原则?
职责分离、配置外置、可续爬、有日志、依赖可复现——
这些习惯让爬虫从"一次性脚本"变成"可维护的小工具"。同时始终遵守合规(见法律红线篇)。
