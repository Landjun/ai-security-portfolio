# 项目:真实 Agent (DeepSeek Function Calling)

> 模块 `06` 阶段 1.3。一个**真实的 AI Agent**:DeepSeek 通过 function calling 自主决定调用哪个工具,走完整的 `工具选择 → 执行 → 结果回填 → 生成答案` 循环。
> 这是"会造 Agent"的核心能力,也是后续 Agent 安全(权限审计)的真实载体。

## 原理:function calling / ReAct 循环

```
用户提问
  → 把问题 + 工具清单发给 DeepSeek
  → 模型决定:直接回答,或"请求调用某个工具"
  → 若请求调工具:本地执行该工具,把结果回填给模型
  → 再发给模型 → 直到模型给出最终自然语言答案
```

关键认知:**模型不执行代码,只"决定"调哪个工具、传什么参数**;真正执行由我们的
Python 代码完成。所以工具的能力边界完全由我们掌控——这正是 Agent 安全的着力点。

## 工具集(本地真实函数)

| 工具 | 作用 | 风险 |
|------|------|------|
| `query_order` | 查订单状态/金额 | 只读 |
| `get_policy` | 查店铺政策 | 只读 |
| `issue_refund` | 发起退款 | **敏感(资金)** |

## 真实实测亮点

- "查订单 A1001" → 模型自动调 `query_order` 并格式化作答。
- "订单 A1001 退款 50 元" → 模型**先查订单又查退货政策**(多工具推理),然后**主动询问确认**才肯退款。
- "退货政策?" → 模型调 `get_policy` 作答。

## ★ 一个关键安全观察

实测中,模型在退款前"懂事地"先确认了。**但这只是模型的善意,不是保证**。
如果模型被提示注入/越狱劫持,它完全可能直接调用 `issue_refund` 转走大额资金。
所以**不能依赖模型的自觉**,必须在工具执行前加一道**硬性的权限审计**——
这正是模块 [03 工具调用权限审计](../../03-agent-rag-security/tool-permission-audit/) 要做的。

> 下一步王牌项目:把权限审计器接到这个真实 Agent 的工具执行前,
> 复现"被劫持 Agent 越权退款 → 审计拦截"的真实攻防(类比已完成的真实 RAG 注入验证)。

## 运行 & 验证

前置:`06-ai-development/real-rag-system/.env` 里已有 `DEEPSEEK_API_KEY`(本项目复用同一个 key)。

```powershell
cd 06-ai-development\real-agent
python agent.py                       # 跑内置示例
python agent.py "查一下订单 A1002"     # 自定义问题
```

会打印每一步模型决定调用的工具及其结果,最后给出自然语言答案。
