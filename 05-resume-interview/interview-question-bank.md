## Part 2 · 三条硬门槛专项追问 + 诚实兜底答法 🔴

> JD 招聘最卡这三条。面试官会反复追问、试图戳穿。**策略:不撒谎、不夸大,承认缺口 + 立刻把话题引到你真做过的强项 demo。**

### 硬门槛 1:有没有真实攻防 / 漏洞挖掘能力(真实环境、真实编号)
- 追问:「你这些都是本地靶场和模拟,有没有在真实/授权环境挖到带编号的漏洞?」
- **答法**:「目前我的真实漏洞编号还在 SRC/Immunefi 平台积累中,这点我不回避。但我的攻防能力不是只停在靶场:① 我在**真实 DeepSeek** 上复现并防御过 RAG 间接注入和 Agent 越权,不是模拟模型;② 我做了完整的代码审计闭环(7 类漏洞→扫描器→报告→修复 8→0);③ 我有自研静态扫描器和方法论。我很清楚靶场≠真实战果,所以正在合法平台把『准备』变成『编号』。」→ 然后主动:「我可以现场讲一个我在真实模型上发现 v1 检测器被绕过、定位根因、升级到 ML 检测把绕过率打到 0 的完整过程。」

### 硬门槛 2:AI 安全 / Agent 实践(不是只会用大模型)
- 追问:「很多人简历写 RAG、Agent、LangChain,但只是调 API。你和他们区别在哪?」
- **答法**:「区别是我既会造也会防,而且都落成可运行代码。造:真实 RAG、function-calling Agent、LangChain Agent、全栈助手码小安(还接了向量库/可观测/评测/MCP/多模态)、甚至用 TS 复刻一遍。防:在这些真实系统上做注入、越权、投毒攻防,并把安全做成可插拔中间件(LLM 安全网关)。我能讲清每个组件的安全边界,比如 Agent 工具执行前的权限审计为什么不能依赖模型自觉。」→ 现场设计题随便出。

### 硬门槛 3:能不能把能力转化为可验证成果
- 追问:「你怎么证明这些是你真做的、有质量?」
- **答法**:「全部开源在 GitHub,45+ 可运行子项目、48 个单测 + TS 测试跑 GitHub Actions CI 常绿,每个项目有原理→复现→防护→检测→面试表达六步法文档和量化结果(红队绕过率 53%→0%、成员推断 AUC 0.93→0.56、模型窃取保真度 95%)。一行命令可复现。我缺的是比赛名次和漏洞编号这类外部背书,这我在补。」

- ❌ 只有 Prompt 使用经验 → 强调你「会造也会防」。
- ❌ 传统安全底座薄弱 → 用 01 八靶场 + 手撕原理顶住。
- ❌ 无任何可验证成果 → 亮 GitHub + CI + 量化指标。
- ❌ 项目讲不清个人贡献 → 全程独立,能讲到代码级细节。
- ❌ 只会用工具不会验证/分析 → 强调审计闭环、PoC、修复。
- ❌ 表达混乱 → 用六步法和 STAR 结构化表达。
- ❌ 把 AI 安全等同于「提示词写得好」→ 讲清模型层 vs 应用层、内生安全。
