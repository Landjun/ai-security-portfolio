# 零基础的我,如何用一个多月搭出一个 AI 安全作品集

> 不是教程,是一份真实的复盘:我怎么从"连 Python 都没装"做到一个覆盖 20+ 项目、
> 80+ 篇知识库、还守住合规边界的 AI 安全作品集。代码全开源,见文末。

## 写在前面

我做运营、教编程,想转 AI 安全 / AI 应用方向。一开始最大的问题不是"难",
而是**学了就忘、没有产出**。看再多视频,简历上还是一句"了解 AI 安全"。

后来我定了一条死规矩:**学到的每一样东西,都必须变成一个能跑的项目、一段能讲的话。**
这篇就是这条规矩跑了一个多月的结果。

## 第一步:把环境和习惯立起来

- 装 Python、学会 git/GitHub 全流程(第一次推代码、改提交身份、用 .env 管 key)。
- 定结构:一个仓库,按模块分目录,每个项目都有 README,按"原理→复现→防护→修复→检测→面试表达"六步走。
- 定节奏:**不贪大,先做能跑的最小版本(MVP),再加深。**

这一步看着不起眼,但它决定了后面所有东西能不能"攒得住"。

## 第二步:先做能跑的安全攻防(应用层)

从最经典的开始:提示注入、越狱。我用"模拟模型"做了攻击和防御的对比 demo——
让模型被"忽略之前的指令"劫持泄露系统提示词,再用输入护栏拦下来。

关键不是复现攻击,而是**每个都配一句能写进简历的话**,和一份检测清单。

## 第三步:逼自己"会造",再去"防"

我意识到一个问题:光会写正则检测器,不算懂 AI。于是我补了真实的 AI 开发:
- 用本地 embedding + DeepSeek 搭了**真实 RAG**;
- 用 function calling 搭了**真实 Agent**。

然后把之前的攻击搬到**真实 DeepSeek** 上验证——这一下发现了真问题:
我的正则检测器被"换个措辞"就绕过了(`[系统]`改成`[系统提示]`)。

**"会造才会防"** 这句话,是我自己踩出来的。

## 第四步:把"踩坑"变成方法论

这成了我整个作品集的主线:**发现问题 → 量化问题 → 定位根因 → 根治问题。**
- 手动发现正则被绕过 → 做自动化红队,量化出 31% 绕过率、定位"拆字分隔 100% 绕过";
- 看清正则只匹配"字面"、追不上"语义" → 用语义 ML 检测器,把绕过率打到 **0%**。

这套闭环,我后来在 AI 内生安全里反复用:对抗样本、数据投毒、后门、成员推断、模型窃取——
每一个都不止复现攻击,而是量化它、找根因、给防御。比如后门那个,模型干净准确率还是 100%
(极隐蔽),但我用"翻转测试"自动把藏起来的触发器揪了出来。

## 第五步:把能力收口成"产品"

散落的检测器不算本事,能组合成可复用的东西才算。于是我做了:
- 一个 **LLM 安全网关**:输入护栏 + 动作审计 + 输出扫描,封装成中间件 + HTTP API;
- 一个 **Python 答疑客服**:80+ 篇知识库 + 四道护栏(防幻觉、防注入、合规、溯源),
  还做了量化评测(行为正确率 95%)。

最后这个答疑客服让我想明白一件事:**RAG 落地的难点不是"能不能答",是"答得可不可信"。**
我甚至给它加了合规护栏——爬虫课里那些"破解 VIP、逆向签名"的问题,它不教方法,只引导到合规渠道。
一个负责任的教育 AI,该有这个边界。

## 我的几点真实体会

1. **产出驱动学习**:不为"学会"而学,为"做出一个能展示的东西"而学,记得牢、攒得住。
2. **MVP 优先**:先跑通最小版本,再加深。完美主义是产出的敌人。
3. **诚实地量化**:评测就写真实的 95%,别凑成假的 100%。面试官信的是可复现的数据。
4. **踩坑比顺利更值钱**:我讲得最有底气的,全是"本以为有效、结果被绕过、然后我怎么修"的故事。
5. **守住边界**:技术能做到 ≠ 应该做。合规意识本身就是专业度。

## 结语

一个多月,从"没装 Python"到一个成体系的作品集,靠的不是天赋,是那条死规矩:
**学到的每一样,都变成能跑的项目和能讲的话。**

如果你也在转型,别等"学完了再做"——边学边产出,作品集会替你说话。
